# v0.3.1

[English →](v0.3.1.md)

## Hermes 插件真的能加载了

`.hermes-plugin/` 之前只有清单没有 `__init__.py`，Hermes 能发现插件却注册失败：
`hermes plugins doctor` 报 `No __init__.py` 退出 1、注册数为 0。现在通过
`ctx.register_skill()` 注册 `skills/pit-stop/SKILL.md`，仓内克隆与扁平化两种安装
布局都能解析。实测：doctor 退出 0。

## Hub 安装不再被拦

Hermes skills hub 的扫描器（skills-guard-v2）把裸 `sudo` 判为 HIGH，把技能包推到
caution，社区源安装得加 `--force` 才能过。护栏参考文档改成描述前缀类别、不再写这个
字面量，并新增一道一致性检查：该词一旦回到技能包里就失败。扫描判定：caution → safe；
`hermes skills update` 现在报 `Allowed (community source, safe verdict)`。

## Hermes 插件安装：硬拦 → 确认安装

`hermes plugins install Finn763/pit-stop` 之前被直接拒绝（dangerous 判定，`--force`
无效），因为本仓文档与测试矩阵里就有破坏性命令字面量。现在 README 演示与护栏矩阵改用
语义等价的非根路径（`rm -rf ./build`、`printf` 取代「把 echo 管道进 shell」的写法），critical 命中
清零：安装器从「直接拒绝」变成「问一次再装」（或 `--force` 直接装）。critical 字面量
没法写进一致性门禁本身——门禁文件会被同一个扫描器判 critical——这类只能靠人工把关。

## 其他

- 一致性门禁的扫描步骤出错时改为 fail-closed，标签也如实写明它只守那一个裸词，
  而不是「所有阻塞性字面量」。
- 护栏参考文档修正：除 `do` 和 `command` 外，其余前缀都允许带 flag；被拦调用的
  描述改为如实说明 hook 与宿主的实际行为。
- `.gitignore` 忽略 `__pycache__/`——插件现在带一个 Python 文件。
