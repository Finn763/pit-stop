## 护栏改由一个启动器拉起，不再走 `.sh` 路径

hook 命令原来是 `bash "$CLAUDE_PROJECT_DIR/hooks/block-destructive.sh"`。这个字面量在 Windows
上有两种失效方式，在 Unix 上有一种。Claude Code 会给任何含 `.sh` 的 hook 命令前再补一个 `bash`，
宿主就可能跑成 `bash bash ...`；而 `bash` 只有在 Git Bash 把它塞进 `PATH` 时才在 `PATH` 上，那又不是
宿主实际拉起的那个 shell。两种情况下 PreToolUse 护栏都什么也没做、也什么都没说——矩阵一直是绿的，
因为它自己直接调脚本，而 CI 的 `windows-latest` 用 `shell: bash`，从没走过宿主的解析这一步。

`hooks/run-hook.cmd` 是个 polyglot：cmd.exe 读批处理那一半，sh/bash 读 Unix 那一半。批处理那半按
`C:\Program Files\Git\bin\bash.exe`、`C:\Program Files (x86)\...`、
`%LOCALAPPDATA%\Programs\Git\bin\bash.exe` 的顺序找 bash，再退到用全路径加 `$PATH:` 调
`where.exe`，这样 `where` 和 `bash` 都不可能来自当前目录，同时跳过 System32、Sysnative、
WindowsApps 里那批没装发行版就失败的 WSL 启动器。它在任何括号块之外透传 hook 的 exit code——块内的
`%ERRORLEVEL%` 在解析时就已经展开了。Unix 那半按最后一个分隔符切 `$0`，不起 `dirname` 子进程。

hook 本体去掉了扩展名——`hooks/block-destructive`，因为宿主扫的是命令里的名字。找不到 bash 时在
stderr 明说一句并放行：拦掉所有 Bash 调用会让会话直接停住，但一个悄悄缺席的护栏比一个会说自己缺席的
更糟。矩阵新增五例，在三种 OS 上分别用 `sh`、`bash`、`cmd` 跑这个启动器。

## 运行状态活得比上下文长

轮次计数、发现台账、尝试台账原来只活在上下文里，一次压缩就没了：一轮跑下来能给自己发免费轮次越过
`--max-rounds`，还能把已经修好的东西再修一遍。现在它们落在 `<target>/.pit-stop/run.md`，第一次动手前
就写，每轮追加，行形状固定（`STATUS:`、`- LEDGER`、`- ATTEMPT`、`- ROUND`）。续跑读
`STATUS: fix <N>`：已经花掉的轮次继续算，`open` 的发现只要已经有 `fixed` 孪生行就不重修，`revert` 的
尝试不重跑。新指令覆盖台账；只有压缩或明确说继续才续跑。

台账自带一个内容为 `*` 的 `.pit-stop/.gitignore`，所以它不会出现在 `git status --porcelain` 里，
也就漂不进复查范围。一致性检查 9 钉住模板的行形状和 skill 让 agent 写入的那个路径。
