## Guardrail hardening (independently reviewed)

- **Security checklist**: the `security` tag grows from one line to 8 fixed checks — XSS,
  injection (SQL/NoSQL/command), SSRF, path traversal, authZ/authN gaps (incl. missing
  tenancy checks), hardcoded secrets in source/logs, unsafe deserialization, race conditions
  (TOCTOU). Secrets are pattern-detected only, never extracted; `.env`-class files follow
  guardrail L1.
- **Attempts ledger**: a failed (reverted) approach is recorded and not re-run — the same
  dead end is never tried twice.
- **Behavior-preservation 4 questions**: before a behavior-preserving fix
  (`delete`/`shrink`/`stdlib`/`native`/`yagni`): same output for every input? same error
  behavior? same side effects and ordering? existing tests pass unmodified? Any no → it is a
  behavior change, not cleanup. Bug/security/perf fixes are exempt — the behavior change IS
  the fix.

## Structure: per-phase references

`references/phases.md` split into four phase files, so each phase can be debugged on its own:

- `references/audit.md` — Load + Find + Propose
- `references/fix.md` — fix rules (ledgers + 4 questions)
- `references/review.md` — adversarial review loop + stop conditions
- `references/report.md` — report rules

SKILL.md core stays at 302 words, well under the 500-word cap. Content unchanged — a pure
structural split.
